Charter is a deliverable contract for long-horizon AI agent runs: a small, declarative file that states which artifacts must exist and which acceptance checks they must pass. The same contract instructs the agent, gates the run with an exit code, and produces an audit report — deterministically, with no LLM judge and no API key.

The failure mode isn't a crash — it's a confident "done"

Long-horizon agents rarely fail loudly. They finish, sound certain, and hand you a report with a missing section, a TODO buried on page four, data files that were never written, or tests that never ran. The current control mechanism — re-reading everything the agent produced — does not survive contact with more than one run a day.

Acceptance criteria in prompts get dropped

Instructions compete with everything else in context. Under pressure, the agent forgets the word count, the required sections, the "don't touch vendored code" rule. Nothing enforces them.

LLM judges are gates made of fog

Useful for fuzzy quality, but expensive, non-deterministic, and hard to audit. You can't block a release on a verdict that changes between runs.

Review doesn't scale with agent throughput

Agents got faster at producing deliverables; humans didn't get faster at checking them. The bottleneck moved to verification — so verification needs to be automatic.

One contract, three uses

Declare the deliverables once in charter.toml. Charter turns the same file into instructions for the agent, a gate for the run, and an audit trail for the human.

1Declare

List every artifact the run must produce and the checks it must pass — existence, length, required sections, forbidden placeholder text, valid JSON, passing tests, anything a command can verify.

# charter.toml
[[deliverable]]
id = "report"
path = "report.md"

  [[deliverable.check]]
  type = "markdown_sections"
  sections = ["Results", "Limitations"]

  [[deliverable.check]]
  type = "no_placeholder"

  [[deliverable.check]]
  type = "command"
  run = "python3 -m pytest -q"

2Gate

Exit code 0 or 1. Put it in CI, in a pre-commit hook, or in the agent loop itself — the failure report is structured so it can be fed straight back to the model for revision.

$ charter check
✗ report — Final report
    ✗ [word_count] report.md has 412 words (< 1500)
    ✗ [no_placeholder] placeholder text found: report.md (2x, e.g. 'TODO')
✓ data — Raw results data
FAIL — 6/8 checks passed, 2 failed

# Claude Code: block the agent from stopping early
$ charter hook claude

3Audit

When the run finishes, get a report with pass/fail per check, file hashes, sizes and timestamps — review the contract verdict instead of re-reading the transcript.

$ charter report -o audit.md
$ charter explain   # contract → agent instructions
$ charter check --json | jq .summary
{
  "checks_total": 14,
  "checks_passed": 14,
  "checks_failed": 0
}

Deterministic checks that compose

A dozen primitives cover most of what "done" means in practice; the command check hands the rest to any validator you already trust.

CheckVerifies
exists / not_exists / file_countrequired artifacts are present (and forbidden ones aren't)
contains / not_containsrequired or forbidden patterns, with min/max occurrence counts
no_placeholderno TODO / FIXME / TBD / lorem-ipsum text left in deliverables
word_count / line_count / min_bytes / max_byteslength and size bounds
markdown_sectionsrequired headings are present
json_validfiles parse as JSON and contain required keys
commandtests, linters, builds, schema validators — anything with an exit code

Evidence, not promises

We evaluated Charter's gate-and-revise loop on IFEval, a public benchmark of 541 prompts with verifiable output constraints, in a paired A/B against single-shot generation from the same model (claude-haiku-4-5), scored with the official IFEval library:

single shot+ Charter gate
prompt-level strict accuracy87.1%93.9% (+6.8 pp, McNemar p ≈ 8×10⁻¹⁰)
constraint types Charter could not express80.0%80.0% — unchanged
extra model calls per prompt—0.17

We publish the limitation up front: a gate can only fix what it can check. The paper reports coverage — which constraint types Charter's generic checks can and cannot express — alongside the gains and costs, and the contract compiler, harness, raw logs, and scoring code ship in the repository so every number traces to a script you can run.
